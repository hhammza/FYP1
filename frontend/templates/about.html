Project Overview

AMRPredict is a full-stack machine learning system developed as a Final Year Project (FYP) in BioInformatics & Machine Learning. The project addresses the global health crisis of Antimicrobial Resistance (AMR) — ranked by the WHO as one of the top ten global public health threats facing humanity.

The system predicts whether a bacterial isolate will be Resistant or Susceptible to a given antibiotic, using two complementary machine learning approaches trained on real genomic data from the BVBRC/PATRIC database. A third model simulates the week-by-week evolution of resistance over time using a biologically-calibrated logistic growth model.

The goal is to demonstrate that machine learning applied to genomic data can predict antibiotic resistance faster and cheaper than traditional laboratory culture testing — potentially giving clinicians actionable information within minutes rather than days.

Project Objectives
01
Binary Resistance Classification
Train a LightGBM model on 90,826 labeled AMR records to classify antibiotic resistance from genomic metadata with AUC-ROC ≥ 0.90.
02
Alignment-Free Genomic Prediction
Build a k-mer frequency RandomForest model that predicts resistance directly from raw FASTA sequences — no reference genome alignment required.
03
Temporal Resistance Forecasting
Simulate week-by-week resistance evolution using a biologically-calibrated logistic growth model parameterised per antibiotic class.
04
Production-Ready Web System
Deploy all models as a full-stack REST API system (Django + Flask) with an interactive web interface for clinical and research use.
Methodology
Phase 1 — Data Collection & Preprocessing

AMR phenotype data (Resistant / Susceptible / Intermediate labels, MIC values, organism metadata) was downloaded from the BVBRC database across 15+ bacterial species. FASTA genome sequences were retrieved for 1,685 isolates. Data was cleaned to remove duplicates, parse MIC strings, extract genus/species from genome names, and merge Intermediate into Resistant for binary classification.

Phase 2 — Feature Engineering

Two distinct feature sets were engineered: (1) 14 tabular features for LightGBM — including MIC value + log + sign, drug class, genus/species, and target-encoded resistance rates per antibiotic, taxon-antibiotic pair, and genus-antibiotic pair; and (2) 256+ k-mer features for RandomForest — 4-mer frequency spectrum from raw FASTA, plus GC content and antibiotic one-hot encoding.

Phase 3 — Model Training & Evaluation

LightGBM was trained with is_unbalance=True and early stopping (30 rounds) on an 80/20 stratified train-test split. The K-mer RandomForest used class_weight='balanced' to handle class imbalance (no SMOTE required for RF). Both models were evaluated on held-out test sets using AUC-ROC as the primary metric.

Phase 4 — Deployment

Models are serialized to disk (LightGBM .txt, RandomForest .pkl) and loaded at Django backend startup via a model registry. The Flask frontend proxies all prediction requests to the Django REST API. All three models include heuristic fallbacks so the system remains functional even if a trained model file is unavailable.

Known Limitations
Formulation Model Missing
A fourth model (Formulation Forecasting) was planned to recommend optimal dosing strategies but was excluded from scope — no publicly available pharmaceutical formulation dataset was found that matches the project's genomic data.
No Real-Time Training Progress
Model training runs in a background thread. There is no WebSocket-based live progress indicator — the UI shows "Training started" but does not stream training logs. A production system would use Celery + Redis for async task queuing.
Timeline is Simulation, Not Trained
The Mutation Timeline uses a biologically-informed logistic growth model, not a trained CNN-LSTM. While results are scientifically plausible, they are simulated rather than learned from empirical time-series data.
No User Authentication
The system has no login/authentication layer. In a clinical deployment, HIPAA/GDPR compliance would require user accounts, audit logging, and encrypted data at rest. This is a research prototype.
