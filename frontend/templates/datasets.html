Dataset 1 · Primary Training Data

AMR Phenotype Records (CSV)

What This Dataset Contains

This is the core tabular dataset sourced from the BVBRC (BV-BRC / PATRIC) database — a United States Department of Energy national database of bacterial genomic and antimicrobial resistance data. It provides the labeled ground-truth used to train the LightGBM gradient boosting model.

Each row represents a single genome–antibiotic test result: a specific bacterial isolate tested against a specific antibiotic. The key label is the Resistant Phenotype column — whether the isolate was found Resistant, Susceptible, or Intermediate.

Files are organized as one CSV per bacterial taxon (e.g., amr_taxon_562_Escherichia_coli.csv). The dataset covers 15+ bacterial species across 62 antibiotics.

Dataset 2 · Genomic Sequences

Bacterial FASTA Genome Sequences

What This Dataset Contains

Raw bacterial whole-genome DNA sequences in FASTA format — the standard bioinformatics format for nucleotide sequences. Each file represents the complete assembled genome of a single bacterial isolate, containing between ~100,000 bp (small genomes) and ~5,000,000 bp (large genomes) of ATCG sequence data.

Files are organized by BVBRC genome ID. A FASTA file begins with a header line (starting with >) followed by the raw nucleotide sequence. These sequences are the input to the K-mer resistance predictor — the model reads the sequence, computes 4-mer frequencies, and classifies resistance without needing a reference genome alignment.

K-mer Feature Extraction Pipeline
1
Read & Clean
Parse FASTA, strip header lines, keep only A/T/C/G nucleotides. First 500,000 bp analyzed.
2
4-mer Sliding Window
Slide a 4-nucleotide window across the full sequence, counting each of 4⁴=256 possible tetranucleotides.
3
Frequency Normalization
Divide each count by total k-mers → frequency vector in [0, 1]. This removes genome length bias.
4
GC Content + Antibiotic
Append GC%, AT%, genome_length/500K, plus one-hot encoding of the antibiotic class (N dimensions).

Why K-mers?

K-mer frequencies capture the compositional "fingerprint" of a genome without requiring alignment to a reference. Resistance genes alter the k-mer composition around insertion sites, making these patterns detectable by machine learning. The approach is alignment-free, works on any assembly quality, and runs in milliseconds.

Reference-free O(n) scan AUC 0.93

Dataset 3 · Linking Layer

Mapped AMR Records

What This Dataset Contains

This is an intermediate linkage dataset — it bridges Dataset 1 (AMR phenotype labels) and Dataset 2 (FASTA sequences). Each row from the AMR CSV files is enriched with a fasta_path column pointing to the actual genome FASTA file for that isolate.

This linkage is essential for training the K-mer RandomForest model: the model needs both the resistance label (from Dataset 1) AND the genome sequence (from Dataset 2). The mapped records provide both in one place.

Not all AMR records have a matching FASTA file — only 1,684 out of 4,252 taxons have genomes available in the database. This linkage step filters to the intersection.

Dataset 4 · Test & Development

Sample / Test Subsets

What This Dataset Contains

Two smaller subsets of Datasets 2 and 3, stored at sample_fasta_output/ and sample_mapped_output/. These contain a curated selection of genomes and their mapped records for rapid prototyping, debugging, and demonstration purposes.

The sample datasets allow the system to be tested on any machine without requiring the full multi-gigabyte FASTA corpus. They are also used by the Train page when demonstrating the CNN-LSTM training pipeline.

Using Your Own FASTA File

The system accepts any bacterial FASTA file as input to the Resistance Prediction and Mutation Timeline pages. You can:

AUse any file from fasta_output/ in the project directory
BDownload a FASTA from NCBI, BVBRC, or UniProt
CPaste a raw FASTA sequence in the text box (Paste Sequence tab)
DUse the Load Sample button for a built-in E. coli K-12 sequence
Minimum 100 bp for K-mer prediction, 50 bp for Timeline. Supports .fasta, .fa, .fna formats.

System Guide

How to Use This System

Step-by-step guide for all three analysis modes and the training pipeline.

Mode 1: AMR Forecasting

Predict resistance from metadata — no genome file needed.

1Go to AMR Forecasting
2Select antibiotic from dropdown
3Enter MIC value & sign (optional)
4Select organism or enter genus/species
5Click Predict Resistance
Input: metadata
Output: R/S + probability
Mode 2: K-mer Prediction

Predict resistance from a genome FASTA file.

1Go to Resistance Prediction
2Select antibiotic
3Upload .fasta file or paste sequence
4Adjust threshold (default 0.5)
5Click Predict Resistance
Input: FASTA sequence
Output: R/S + k-mer chart
Mode 3: Mutation Timeline

Simulate week-by-week resistance evolution.

1Go to Mutation Timeline
2Select antibiotic
3Set number of simulation weeks
4Upload FASTA or paste sequence
5Click Generate Timeline
Input: FASTA + weeks
Output: evolution chart
Mode 4: Training

Retrain models on your local data (optional — models are pre-trained).

BVia CLI in backend/ folder
Cpython train_models.py --model all
DModels auto-reload after training
LightGBM: ~3 min
